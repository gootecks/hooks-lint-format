hooks-lint-format

Shared git hooks, linters, formatters and release automation for gootecks repos. Each directory holds a canonical config and a README. Repos consume the kit by version (tag v0.4.0): the Pkl package hk-base, the script tool and the task include.

At a glance

Tool What it does

mise Pins hk, actionlint, zizmor, rumdl, uv, oxfmt, oxlint and the script tool; includes shared tasks
oxfmt Formats code and config; ignores Markdown

actionlint Checks workflow syntax and expressions

git-cliff Writes the changelog and the release notes

Tool versions are in mise/mise.toml; the hk version also appears in the URLs of hk/hk.pkl. Type-aware linting uses tsrs-lint only.

Commit lifecycle

  • pre-commit applies fixes and stages them. stash = "git" stashes unstaged changes first, so fixes only touch what is being committed.
  • commit-msg is the only commit message hook in the shared config. The czg prompt for a plain git commit comes from the user's own ~/.config/hk/config.pkl.
  • commit-msg runs Builtins.check_conventional_commit and rejects messages that are not Conventional Commits. commitizen reads those messages to pick the next version.
  • check makes no fixes, no staging and no stash; CI runs it. fix applies fixes to the working tree and stages nothing.

Steps

Step Files Check Fix
actionlint .github/workflows/*.yml builtin none
oxfmt JS/TS, JSON, YAML, TOML, CSS, HTML, more builtin builtin
nlpm whole repository (tracked SKILL.md, AGENTS.md, agents, commands, .claude) hlf-nlpm-check (needs uv; reads .claude/nlpm.local.md) none; /nlpm:score stays a manual pass
oxlint JS/TS --type-aware --type-check --deny-warnings same flags plus --fix
rumdl **/*.md, **/*.markdown, **/*.mdx rumdl check --deny-config-warnings and hlf-rumdl-docs-check hlf-rumdl-fix
zizmor workflows, action.yml, dependabot builtin builtin, zizmor --fix

hk runs steps in parallel and no step depends on another. oxfmt ignores Markdown through ignorePatterns in .oxfmtrc.json, so rumdl alone formats and lints it. --deny-config-warnings makes a misspelled key in .rumdl.toml fail the step. Details per step: hk/README.md.

Note

The zizmor fix command rewrites workflow files. In the fix and pre-commit hooks it runs on every workflow change, and pre-commit stages the result. Review the staged diff.

Tools

hk

hk/README.md

Runs every step as git hooks and as hk check / hk fix. The shared base hk.pkl ships as the hk-base Pkl package; a repository amends it.

  • exclude hides agent state (.omp, .agents), Obsidian app state (.obsidian), build output, generated files and CHANGELOG.md. A failing Markdown check on the changelog would leave a half-done version bump.
  • hlf-rumdl-fix runs rumdl check --fix and the docs check, then launches the repo-markdown-fixer agent once for the leftovers and checks again. RUMDL_AGENT=0 or CI runs no agent; findings still fail the step.
  • HK=0 runs one command without hk (use it for cz bump). Escape hatches are for one situation each, never for a large number of findings: see docs/lint-policy.md.

mise

mise/README.md

Pins every tool hk runs, so a clone, a teammate and CI get the same versions. mise.toml holds the pins.

  • oxfmt and oxlint come from mise rather than devDependencies: lint versions change in one file and bun install stays out of the hook path.
  • The pkl amends and import URLs pin hk's config schema separately; keep them on the same version as the hk pin.
  • The global mise config sets OXLINT_TSGOLINT_PATH to ~/.local/bin/tsrs-lint. A shell-level export does not win: mise shims apply [env] when they run oxlint.
  • The script tool "github:gootecks/hooks-lint-format" provides hlf-rumdl-fix and hlf-rumdl-docs-check. Shared tasks pre-commit and release:preview come from the task include git::https://github.com/gootecks/hooks-lint-format.git//tasks?ref=v0.4.0. The consumer mise.toml also needs [settings] experimental = true, because mise skips git:: includes otherwise and CI has no global setting.

oxfmt

oxfmt/README.md

Prettier-compatible formatter in Rust for JS/TS, JSON, YAML, TOML, CSS, HTML and more. It replaced a Prettier hook: same output style, one native binary, no node_modules needed to format.

Important

oxfmt does not format Markdown. ignorePatterns in .oxfmtrc.json lists .md, .markdown and .mdx, so editors and direct oxfmt runs skip them too. rumdl owns Markdown.

  • printWidth: 120 fits a side-by-side diff on a laptop and avoids wrapping long literals.
  • singleQuote: true matches the existing TS style; a quote flip would touch every file.
  • sortPackageJson: false keeps package.json key order and avoids a noisy first-adoption diff.
  • Further ignorePatterns entries need a reason (lint policy).

oxlint + tsrs-lint

oxlint/README.md

The hk step runs:

oxlint --type-aware --type-check --deny-warnings {{files}}
  • --type-aware enables rules that need types, such as typescript/no-floating-promises.
  • --type-check also reports TypeScript compiler errors, replacing a separate tsc --noEmit hook.
  • --deny-warnings fails on warnings, so nothing stays at "warn" forever.

Backend: tsrs-lint only. The type-aware backend is tsrs-lint from oxc-project/tsrs. Nothing in the kit installs or references tsgolint.

  • Local: the global mise task tsrs:install (in ~/.config/mise) builds tsrs with cargo into ~/.local/bin. CI installs the tsrs package with bun and links its tsrs-lint launcher to the same path.
  • If OXLINT_TSGOLINT_PATH is set and the file is missing, oxlint fails instead of searching PATH, so a machine without tsrs-lint fails loudly.
  • Check the install with ~/.local/bin/tsrs --version and test -x ~/.local/bin/tsrs-lint. tsrs-lint itself rejects --version.
  • .oxlintrc.json has one override: typescript/await-thenable is off for **/*.test.ts, because Bun's types make expect(promise).rejects look non-thenable and removing the needed await would make those tests pass vacuously.
  • A backlog from --type-check on an existing codebase is fixed, not silenced: oxlint/README.md has the procedure.

rumdl

rumdl/README.md

The only tool that formats and lints Markdown. The shared .rumdl.toml sets the rules; hlf-rumdl-docs-check adds the kit's callout and stale-reference checks; hlf-rumdl-fix applies the auto-fix, then asks repo-markdown-fixer to fix what is left. Style rules: docs/markdown-convention.md. Every rule and its setting: docs/rumdl-rules.md.

actionlint

actionlint/README.md

Checks workflow YAML structure, ${{ }} expressions and types, needs/matrix references, runner labels and action inputs. With shellcheck on PATH it also checks run: scripts.

  • Check-only builtin; no fixer and no config file. Add .github/actionlint.yaml only for self-hosted runner labels.
  • actionlint answers "will it run"; zizmor answers "is it safe". Both run on the same files.

zizmor

zizmor/README.md

Audits workflows, composite actions and dependabot.yml for security problems. The builtin defines a check (zizmor --no-progress) and a fix (zizmor --no-progress --fix); the fix applies safe fixes only, and some need network access and a GitHub token.

  • Actions are pinned by commit SHA with the tag as a comment (unpinned-uses).
  • actions/checkout uses persist-credentials: false (artipacked).
  • permissions: contents: read at the top; wider grants only on the job that needs them.
  • ${{ }} values reach run: through env:, never inline (template-injection).
  • A suppression is a last resort, written as # zizmor: ignore[<audit>] with a reason: see zizmor/README.md.

Commit prompt

The czg prompt is not part of the shared config. It lives in the user's ~/.config/hk/config.pkl; the shared commit-msg check applies either way.

commitizen

commitizen/README.md

Python cz bumps the version, rewrites version_files and tags, from .cz.toml. git-cliff writes CHANGELOG.md.

  • version_provider = "npm" reads and writes package.json. Use cargo, pep621 or uv elsewhere.
  • tag_format = "v$version" matches existing vX.Y.Z tags.
  • pre_bump_hooks runs git-cliff --prepend CHANGELOG.md, so the new section lands in the tagged release commit. commitizen does not read the file.
  • bump_message = "chore(release): v$new_version" keeps the bump commit valid and unable to trigger another bump.
  • cz bump --get-next exits 21 when no commit is a fix, feat or breaking change. Set HK=0 for a local cz bump.
  • cz is not in the mise [tools] table; where it is installed: commitizen/README.md.

Markdown and policy

  • Markdown convention: how Markdown is written and formatted so it renders the same on GitHub and in Obsidian.
  • Lint policy: a rule, check or hook is never turned off or skipped because it reports many findings; findings are fixed.
  • rumdl rule table: each rumdl rule with its setting, whether it auto-fixes, and the reason.
  • docs-drift and unslop are global tasks documented in the maintainer's ~/.config/mise, not part of the kit.

CI

hk.yml runs hk check --all on pull requests and pushes to main, so a commit made with --no-verify, HK=0 or without hooks installed is still checked. See github/README.md.

  1. jdx/mise-action installs every tool in the [tools] table of mise.toml, including the script tool, and applies its [env].
  2. bun add -g tsrs@<version> provides tsrs-lint, linked to ~/.local/bin/tsrs-lint. The pin lives in hk.yml.
  3. The repo's own dependency install lets type-aware lint resolve imports.
  4. hk check --all runs the check hook: no fixes, no agent.
Important

A required status check can only be enforced where GitHub offers protected branches or rulesets for the repository. On a private repository on GitHub Free, hk / check is advisory. Details: github/README.md.

Release

release.yml runs on every push to main, so merging a PR is the release trigger. It needs .cz.toml from commitizen.

  1. cz bump --get-next reads the Conventional Commits since the last tag. Exit code 21 means nothing to release and the run ends green.
  2. git-cliff --unreleased --strip all produces the release notes. cz bump --yes then runs the pre_bump_hooks that prepend the section to CHANGELOG.md, updates version files, commits chore(release): vX.Y.Z and tags vX.Y.Z.
  3. git push --atomic sends the commit and tag to main together.
  4. gh release create --verify-tag publishes the GitHub Release with the notes.
  • Only the default GITHUB_TOKEN is used, with contents: write on the job. Its pushes do not start other workflows, so the bump commit cannot loop and on: release workflows do not fire. Use a PAT or GitHub App token when a release must trigger another workflow.
  • main must accept pushes from github-actions[bot]; a protected branch needs a bypass.
  • concurrency: release runs one release at a time. If main moves during a run the push fails and the next run releases everything.
  • A tag matching tag_format must already exist; create the first tag by hand. Repositories that build release assets add build steps between the bump and the push.

Adopt

Use the maintainer's global repo-adopt task, which is interactive, asks per norm and only adds. It writes an hk.pkl amending the hk-base package, the mise.toml pins including the script tool and uv, the task include, and optional commitizen and CI files. --dry-run shows the changes; --yes norm1,norm2 accepts named norms for agents. A repository with an older kit copy is moved to the versioned form by the same task. The ordered procedure is in skills/hooks-lint-format/SKILL.md; the hooks-lint-format skill runs it.
