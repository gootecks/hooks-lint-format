Versions change in this repo first, then in each repo. Every copied file keeps a first-line comment naming its source directory, where the format allows comments. Type-aware linting uses tsrs-lint only.

Commit lifecycle

  • pre-commit applies fixes and stages them. stash = "git" stashes unstaged changes first, so fixes only touch what is being committed.
  • prepare-commit-msg opens the czg prompt for a plain git commit. It does nothing when a message already exists, under CI or HK_AGENT, or without a terminal.
  • commit-msg runs Builtins.check_conventional_commit and rejects messages that are not Conventional Commits. commitizen reads those messages to pick the next version.
  • check makes no fixes, no staging and no stash; CI runs it. fix applies fixes to the working tree and stages nothing.

Tools

hk

2.12.0hk/README.md

Runs every linter and formatter as git hooks and as hk check / hk fix. hk.pkl is the canonical config; hooks/rumdl-fix.sh is the Markdown fix command.

  • exclude hides agent state (.omp, .agents), build output, generated files and CHANGELOG.md. A failing Markdown check on the changelog would leave a half-done version bump.
  • rumdl has depends = "oxfmt", so it only sees formatted Markdown. Otherwise the two fight over list markers and tables.
  • rumdl-fix.sh runs rumdl check --fix, then launches the repo-markdown-fixer agent once for the leftovers. RUMDL_AGENT=0 or CI skips the agent.
  • HK=0 disables hk for one command (use it for cz bump). HK_SKIP_STEPS=oxfmt git commit ... skips named steps.

mise

pins all toolsmise/README.md

Pins every tool hk runs, so a clone, a teammate and CI get the same versions. mise.toml holds the pins.

  • oxfmt and oxlint come from mise rather than devDependencies: lint versions change in one file and bun install stays out of the hook path.
  • The hk pkl amends URL pins hk's config schema separately. Keep it on the same version as the hk pin.
  • [env] sets OXLINT_TSGOLINT_PATH to ~/.local/bin/tsrs-lint. A shell-level export does not win: mise shims apply [env] when they run oxlint.
  • Tasks: tsrs:install, pre-commit, release:preview. commitizen runs through uvx with a pinned version because mise's pipx backend is off on these machines.

oxfmt

0.77.0oxfmt/README.md

Prettier-compatible formatter in Rust, run on JS/TS, JSON, YAML, TOML, Markdown, CSS, HTML and more. It replaced a Prettier hook: same output style, one native binary, no node_modules needed to format.

  • printWidth: 120 fits a side-by-side diff on a laptop and avoids wrapping long literals and type signatures.
  • singleQuote: true matches the existing TS style; a quote flip would touch every file.
  • sortPackageJson: false keeps package.json key order. The default sort makes a noisy first-adoption diff.
  • ignorePatterns lists files it must not touch: third-party text, **/*.icon/**, fixtures whose bytes matter.

oxlint + tsrs-lint

oxlint 1.92.0 · tsrs-lint 0.25.0oxlint/README.md

The hk step runs:

oxlint --type-aware --type-check --deny-warnings {{files}}
  • --type-aware enables rules that need types, such as typescript/no-floating-promises.
  • --type-check also reports TypeScript compiler errors, replacing a separate tsc --noEmit hook.
  • --deny-warnings fails on warnings, so nothing stays at "warn" forever.

Backend: tsrs-lint only. The type-aware backend is tsrs-lint from oxc-project/tsrs, a Rust port of the TypeScript 7 checker. There is no tsgolint anywhere in the kit.

  • Local: mise run tsrs:install builds tsrs with cargo into ~/.local/bin.
  • CI: the npm tsrs package is installed and its tsrs-lint launcher is linked to the same path.
  • OXLINT_TSGOLINT_PATH names the binary. If it is set and the file is missing, oxlint hard-fails instead of searching PATH, so a machine without tsrs-lint fails loudly.
  • Measured on icon-composer-mcp src/: 0.18 s with tsrs-lint against 1.0 s with tsgolint.
  • .oxlintrc.json has one override: typescript/await-thenable is off for **/*.test.ts. Bun's types make expect(promise).rejects look non-thenable, and removing the needed await would make those tests pass vacuously.
  • On an existing codebase --type-check surfaces a backlog (399 errors at first, 339 from noUncheckedIndexedAccess). Count errors by code with -f json and decide per flag, not per line.

rumdl

0.3.2rumdl/README.md

Shared .rumdl.toml for Markdown formatted by oxfmt.

  • Formatting rules follow rumdl's prettier-compatible example, because oxfmt rewrites that output: MD004, MD007, MD029, MD049, MD050, MD060.
  • Structure rules follow google-style where the formatter has no say: MD003 ATX headings, MD046 fenced code, MD009. Google's bullets and indent are not used; oxfmt would rewrite them.
  • MD076 is off: oxfmt sets list looseness per item, so mixed lists are valid.
  • MD013 is off: oxfmt does not wrap prose, so line length would only flag existing text.

actionlint

1.7.12actionlint/README.md

Checks workflow YAML structure, ${{ }} expressions and types, needs/matrix references, runner labels and action inputs. With shellcheck on PATH it also checks run: scripts.

  • Check-only builtin; no fixer and no config file. Add .github/actionlint.yaml only for self-hosted runner labels.
  • actionlint answers "will it run"; zizmor answers "is it safe". Both run on the same files.

zizmor

1.30.1zizmor/README.md

Audits workflows, composite actions and dependabot.yml for security problems. Check-only builtin; zizmor --fix applies safe fixes by hand.

  • Actions are pinned by commit SHA with the tag as a comment (unpinned-uses).
  • actions/checkout uses persist-credentials: false, so the token is not left in .git/config (artipacked).
  • permissions: contents: read at the top; wider grants only on the job that needs them.
  • ${{ }} values reach run: through env:, never inline (template-injection).
  • Suppress with # zizmor: ignore[<audit>] and a reason, placed after run: |, not inside the block.

czg

1.14.0czg/README.md

Interactive prompt that writes a Conventional Commit message, opened by hk's prepare-commit-msg for a plain git commit.

  • It exits without prompting when a message exists, when CI or HK_AGENT is set (automation never blocks), or when there is no /dev/tty.
  • It is a personal tool, not pinned in mise.toml. Install once per machine: bun add -g czg@1.14.0. Without it the commit continues with the normal editor.
  • It writes messages only. Versioning belongs to commitizen, which reads a different config.

commitizen

4.19.3commitizen/README.md

Python cz bumps the version, writes CHANGELOG.md and tags, from .cz.toml.

  • version_provider = "npm" reads and writes package.json. Use cargo, pep621 or uv elsewhere.
  • tag_format = "v$version" matches existing vX.Y.Z tags.
  • update_changelog_on_bump with changelog_incremental adds one section per release and leaves older ones alone.
  • bump_message = "chore(release): v$new_version" keeps the bump commit valid and unable to trigger another bump.
  • cz bump --get-next exits 21 when no commit is a fix, feat or breaking change. Set HK=0 for local cz bump.

CI

hk.yml runs hk check --all on pull requests and pushes to main, so a commit made with --no-verify, HK=0 or without hooks installed is still checked. See github/README.md.

  1. jdx/mise-action installs every tool pinned in mise.toml and applies its [env], including OXLINT_TSGOLINT_PATH.
  2. npm install -g tsrs@<version> provides tsrs-lint, linked to ~/.local/bin/tsrs-lint. Match the version to the local build.
  3. The repo's own dependency install lets type-aware lint resolve imports.
  4. hk check --all runs the check hook: no fixes, no agent.

Make the check job a required status check on main.

Release

release.yml runs on every push to main, so merging a PR is the release trigger. It needs .cz.toml from commitizen.

  1. cz bump --get-next reads the Conventional Commits since the last tag. Exit code 21 means nothing to release and the run ends green.
  2. cz changelog --dry-run --unreleased-version produces the release notes. cz bump --yes then updates version files and CHANGELOG.md, commits chore(release): vX.Y.Z and tags vX.Y.Z.
  3. git push --atomic sends the commit and tag to main together.
  4. gh release create --verify-tag publishes the GitHub Release with the notes.
  • Only the default GITHUB_TOKEN is used, with contents: write on the job. Its pushes do not start other workflows, so the bump commit cannot loop and on: release workflows do not fire. Use a PAT or GitHub App token when a release must trigger another workflow.
  • main must accept pushes from github-actions[bot]; a protected branch needs a bypass.
  • concurrency: release runs one release at a time. If main moves during a run the push fails and the next run releases everything.

Adopt

  1. Copy the configs: hk.pkl, hooks/rumdl-fix.sh (chmod +x), .oxfmtrc.json, .oxlintrc.json, .rumdl.toml, .cz.toml. Extend exclude and ignorePatterns; delete steps the repo has no files for.
  2. Merge [tools], [env] and the tasks from mise/mise.toml into the repo's mise.toml, then run mise install.
  3. Run mise run tsrs:install once per machine and confirm ~/.local/bin/tsrs-lint --version works.
  4. Run hk install once per clone.
  5. Run hk check --all. It must pass before the first commit with hooks; fix the backlog first.
  6. Copy github/hk.yml and github/release.yml to .github/workflows/.

To do this on a repo, use the hooks-lint-format skill: skills/hooks-lint-format/SKILL.md.
